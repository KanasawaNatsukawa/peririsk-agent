# Agent 优化记录：从三工具到可校验的五工具链路

日期：2026-10-28

## 目标

不为了增加工具数量而堆功能，只增加能够改变 Agent 决策路径、并且可测试的本地能力。

## 新增工具

### validate_case_data

检查：

- 患者必要字段是否完整；
- PPG 采样点数；
- 有效采样点比例；
- 波形最小值和最大值；
- 波形峰峰值；
- 是否能够继续进行分析。

### compare_hr_windows

对同一病例比较多个时间窗口：

- 每个窗口的检测心跳次数；
- 算法心率；
- PLETH_HR 和综合 HR；
- 窗口间最大心率差；
- 是否超过稳定性阈值。

## Agent 路径变化

完整评估默认路径：

```text
查病历
→ 检查病例和波形质量
→ 分析 60 秒 PPG 心率
→ 差值超过 3 次/分时比较 30/60 秒窗口
→ ASA 分级
→ 生成三段式报告
→ 程序校验报告
```

限定任务路径：

```text
用户只要求心率
→ 查病历
→ 检查数据质量
→ 分析波形
→ 直接回答心率
```

该路径不会调用 ASA，也不会生成完整三段式报告。

## 程序化报告校验

新增 `report_guard.py`，检查：

- 是否包含风险评估、麻醉关注点、建议三部分；
- 是否出现性别、舒张压、高血压诊断、冠脉造影等禁止字段；
- 是否出现未转换的 true/false；
- 列表型结论是否附带“（依据：…）”；
- 不通过时最多要求模型修正两次。

该机制是提示词之外的确定性检查，但仍不等同于完整临床事实核验。

## 真实运行结果

### 仅计算心率

使用陈伟 `case_004`：

```text
get_patient_record
→ validate_case_data
→ analyze_waveform
→ 直接返回心率
```

结果为：

- 算法心率 85.0 次/分；
- PLETH_HR 86.2 次/分；
- 综合 HR 85.5 次/分；
- 未调用 ASA；
- 未生成完整风险评估报告。

### 危重病例的稳定性分支

使用赵芳 `case_005`：

```text
get_patient_record
→ validate_case_data
→ analyze_waveform(60 秒)
→ compare_hr_windows([30, 60])
→ assess_asa_grade
```

60 秒算法心率与 PLETH_HR 差值为 3.8 次/分，超过阈值，因此触发窗口复核：

- 30 秒算法心率 102.0；
- 60 秒算法心率 98.0；
- 最大窗口差 4.0 次/分；
- 判定不稳定。

- 工具调用顺序：5/5；

## 数字孪生推演舱

新增 `twin_lab.py` 和网页第二个标签页，提供现场可交互的确定性推演：

- 切换 20 个病例，查看 5、10、30、60 秒 PPG；
- 在波形峰上显示本地 scipy 检测到的红点；
- 拖动虚拟收缩压，实时观察 ASA 基础级别与血压地板如何取最大值；
- 注入「缺少收缩压」「波形平直」「心率冲突」三类故障；
- 根据故障改变 Agent 工具路径，演示数据质量门槛和窗口复核分支；
- 全部计算在本地内存完成，不调用大模型，也不修改病例文件。

60 秒选项便于直接对照默认心率分析口径；ECharts 内置缩放仍可放大查看局部峰值和异常段。

### 120 秒原始数据与自动选窗

20 个病例的原始数据均为连续 120 秒，每例 60000 个采样点。`analyze_waveform` 和 `validate_case_data` 会在运行时按 5 秒步长检查 13 个候选 60 秒窗口，选择规则依次为：

1. 有效采样率和波形幅度必须可用；
2. 异常采样点数和缺失采样点数更少；
3. 前后两个 30 秒窗口的算法心率更稳定；
4. 条件相同时优先较早窗口。

选窗过程不读取 PLETH_HR 或综合 HR，避免根据参考答案反向挑选窗口。前五个病例自动选中的窗口为：

| 病例 | 窗口（秒） | 算法心率 |
|---|---:|---:|
| case_001 | 5–65 | 87 |
| case_002 | 5–65 | 78 |
| case_003 | 10–70 | 73 |
| case_004 | 45–105 | 86 |
| case_005 | 25–85 | 101 |

20 例最终平均同源 PLETH_HR 差约 1.3，综合 HR 平均差约 1.8 次/分。该结果仍只说明工程可行性，不是临床准确率。

### 全候选窗口评估与热力图

新增 `python evaluate.py --windows-only`，一次评估 20 个病例的全部 260 个候选窗口，不调用大模型：

- `window_evaluation_results.csv`：每个窗口的有效采样率、异常点、缺失点、前后半段心率差、算法心率、两个参考值和误差；
- `window_evaluation_summary.csv`：每个病例选中窗口、全窗均值、中位数、最差值，以及全病例汇总；
- `window_policy_comparison.csv`：固定首窗、仅信号质量、质量+稳定性和参考最优四种策略的逐病例结果；
- 网页推演舱新增选窗质量热力图和 13 行候选明细，黄色边框标记工具实际选择的窗口。

评估结果：

- 工具选中窗口的平均同源差为 1.3 次/分，最差为 4.6；
- 全部 260 个候选窗口的同源差均值为 1.8，中位数为 0.9，最差为 13.9；
- 全部 260 个候选窗口的综合 HR 差均值为 2.2，中位数为 1.4，最差为 16.4；
- 部分病例的质量最优窗口并不是同源差最小的窗口，说明选窗规则没有按参考答案反向挑选。

热力图也明确标注：“同源差（仅评估）”不参与选窗。

四种策略在 20 病例上的同源差结果：

| 策略 | 均值 | 中位数 | 最差 |
|---|---:|---:|---:|
| 固定首窗 | 2.8 | 1.4 | 9.0 |
| 仅信号质量 | 2.2 | 0.9 | 9.0 |
| 质量+稳定性 | 1.3 | 0.9 | 4.6 |
| 参考最优（仅评估） | 0.4 | 0.1 | 1.9 |

当前部署策略在同源误差均值和最差值上都优于固定首窗和仅信号质量策略。参考最优是使用参考答案选出的理论上界，只用来衡量提升空间。

### 心率参数网格搜索

新增 `python evaluate.py --tune-heart-rate`，在全部 260 个候选窗口上比较：

- `prominence`：`0.1–1.0`；
- `min_distance_seconds`：`0.3/0.4/0.5/0.6`；
- 共 40 组组合，不使用 DeepSeek。

搜索结果写入 `heart_rate_parameter_search.csv`。稳健评分同时考虑全部窗口同源差均值、最差值、综合 HR 均值，以及实际选中窗口的误差。

20 例复核后，`prominence=0.5`、`distance=0.4` 进入稳健评分最优平台，全部窗口同源差均值 1.832、同源差≤3 的比例 78%。因此保留原默认值，不需要根据早期 5 例的轻微差异调整。

### 扩展 ASA 输入

患者档案与 `assess_asa_grade` 新增：

- `BMI`：30–39.9 至少 II，≥40 至少 III；
- 活动性恶性肿瘤：简化规则为至少 III；
- 急诊手术：只追加 ASA 的 `E` 标识，不自动抬高数字等级；
- 困难气道：返回围术期关注，不改变 ASA 数字等级。

这些规则只用于教学演示。正式 ASA 分级必须由麻醉医生结合完整临床资料判断。

PPG 图使用 Streamlit 原生 `st.echarts_chart`。此前 Altair 分层图在当前 Streamlit 与 Altair 组合下只显示坐标轴，Vega 报告数据范围为无穷；迁移后可稳定显示曲线、面积、检测峰和缩放交互。

### 原始波形异常处理

人工检查 20 秒窗口时发现三类由原始数据导致的竖线：

- `case_002` 起始约 1.45 秒的基线位于负值区，随后突然跳到正常正区间，属于起始基线未稳定；
- `case_003` 开头 188 个采样点为 `25686.95` 哨兵值；
- `case_004` 在约 8.55 秒和 14.47–14.48 秒出现 `-198.25` 哨兵低谷。

处理方式不是覆盖原始 CSV，而是在内存中生成两张异常掩码：

- 显示掩码同时包含幅度哨兵和起始基线未稳定片段，图表用 `null` 断开连线，不再跨异常段画垂直线；
- 峰值检测掩码只包含幅度哨兵，使用局部线性插值后执行 `find_peaks`，避免剔除正常脉搏波而改变已核验的 60 秒心率。

自动选窗会避开这些异常片段；原始 CSV 仍保留用于追溯。页面热力图会显示每个候选窗口的异常点数量，数据质量工具也会区分“显示异常”与“影响峰值检测的异常”。
