# VitalDB 多病例对齐数据

由 `scripts/build_vitaldb_cases.py` 生成，共 20 个经过质量筛选的病例喵。每个病例都从固定来源锚点截取连续 120 秒：

- `waveform_120s.csv`：PLETH 波形，500Hz，60000 点
- `numeric_120s.csv`：`Solar8000/HR` 与 `Solar8000/PLETH_HR`

提取阶段要求 PLETH 有效率 ≥90%、两条心率轨道各有足够有效读数，并排除算法心率超出 `30–180`、同源差大于 `5` 或综合 HR 差大于 `8` 的严重失真病例。该参考值只用于病例级异常拒绝，不参与运行时 60 秒窗口选择。

运行时的 `tools/waveform.py` 会在 120 秒原始数据中按 5 秒步长扫描 13 个候选 60 秒窗口，依次考虑缺失率、异常点数量、幅度有效性和前后半段心率差。选窗过程不读取参考心率。

`manifest.csv` 记录来源病例、120 秒来源起点、采样点数、有效参考读数，以及病例级质量门槛检查时得到的选中窗口和心率差异。

## 原始数据质量限制

原始 120 秒数据仍保留 VitalDB 采集时可能出现的监护仪哨兵值和基线台阶，例如 `case_003` 开头的 `25686.95` 和 `case_004` 的 `-198.25`。运行时选窗会避开这类片段，而不是修改或覆盖原始 CSV。

原始 CSV 保留用于可追溯性。当前结果仍是 20 个病例的工程演示，不是临床准确率证据。
